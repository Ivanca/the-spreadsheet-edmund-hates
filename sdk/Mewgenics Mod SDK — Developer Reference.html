Mewgenics Mod SDK

Build NativeAOT mods for Mewgenics — access live game data, hook functions, fire events, and control items.

NativeAOT .NET 8 · C# win-x64 SDK v2.2

Architecture

Mewgenics loads mods via DLL side-loading: version.dll is placed next to Mewgenics.exe and the OS loads it automatically on startup. This DLL (MewgenicsCore) bootstraps the framework, installs game hooks, and scans Mods/*.dll to load individual mods.

Mewgenics.exe starts
  └─► OS loads version.dll (MewgenicsCore — NativeAOT)
          ├── Installs game hooks (Gold, Inventory, Tooltip, …)
          ├── Publishes GameEvents to all mods
          ├── Renders in-game overlay + ConfigPanel
          └── Scans Mods/*.dll → calls MewMod_Init(api*) on each

Each mod is a separate NativeAOT DLL exporting five C-ABI functions. The SDK provides a base class (MewgenicsMod) and boilerplate exports so you only write gameplay logic.

Quick Start

A minimal mod in 3 files:

1. Create the project

# MyMod.csproj
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Library</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <AllowUnsafeBlocks>true</AllowUnsafeBlocks>
    <Nullable>enable</Nullable>
    <PublishAot>true</PublishAot>
    <RuntimeIdentifier>win-x64</RuntimeIdentifier>
    <SelfContained>true</SelfContained>
    <SuppressTrimAnalysisWarnings>true</SuppressTrimAnalysisWarnings>
  </PropertyGroup>
  <ItemGroup>
    <!-- Référence la SDK DLL locale (sdk/ dans ton projet) -->
    <Reference Include="MewgenicsModSdk">
      <HintPath>sdk\MewgenicsModSdk.dll</HintPath>
    </Reference>
  </ItemGroup>
</Project>

2. Implement the mod

using MewgenicsModSdk;
using MewgenicsModSdk.Game;

namespace MyMod;

public class MyMod : MewgenicsMod
{
    public override string Id          => "my_mod";
    public override string Name        => "My Mod";
    public override string Version     => "1.0.0";
    public override string Description => "Does something cool.";
    public override string Category    => "Gameplay";

    protected override void OnLoad()
    {
        Log("MyMod: loaded");
        GameEvents.OnHouseUpdate += OnFrame;
    }

    protected override void OnEnable()  => Log("MyMod: enabled");
    protected override void OnDisable() => Log("MyMod: disabled");

    private void OnFrame(HouseUpdateEvent e)
    {
        if (!IsEnabled) return;
        // runs every game frame
    }
}

3. Export the C-ABI entry points

using MewgenicsModSdk;
using MewgenicsModSdk.Api;
using System.Runtime.InteropServices;

namespace MyMod;

internal static unsafe class Exports
{
    private static readonly MyMod _mod = new();

    [UnmanagedCallersOnly(EntryPoint = "MewMod_GetInfo")]
    public static ModInfo* GetInfo()       { try { return ModInfoHelper.GetInfo(_mod); } catch { return null; } }

    [UnmanagedCallersOnly(EntryPoint = "MewMod_Init")]
    public static void Init(MewgenicsApi* api) { try { _mod.InternalLoad(api); } catch { } }

    [UnmanagedCallersOnly(EntryPoint = "MewMod_Enable")]
    public static void Enable()           { try { _mod.InternalEnable(); } catch { } }

    [UnmanagedCallersOnly(EntryPoint = "MewMod_Disable")]
    public static void Disable()          { try { _mod.InternalDisable(); } catch { } }

    [UnmanagedCallersOnly(EntryPoint = "MewMod_ConfigReload")]
    public static void ConfigReload()     { try { _mod.InternalConfigReload(); } catch { } }
}

Distribution & Build

What you receive

The SDK is distributed as two files to place in a sdk/ folder inside your project:

  • MewgenicsModSdk.dll — the compiled library (referenced at build time)
  • MewgenicsModSdk.xml — IntelliSense documentation (tooltips in VS / Rider)
No source code needed The DLL is statically linked into your mod during dotnet publish --aot. It is not distributed with your mod or with the game.

Requirements

  • .NET 8 SDK: dotnet.microsoft.com
  • Visual Studio 2022 or VS Build Tools with Desktop Development with C++ (required by the NativeAOT linker)
  • Windows x64 only

1. Create the project

Recommended structure:

MyMod/
├── sdk/
│   ├── MewgenicsModSdk.dll
│   └── MewgenicsModSdk.xml
├── MyMod.csproj
└── MyMod.cs

2. Configure the .csproj

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Library</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <AllowUnsafeBlocks>true</AllowUnsafeBlocks>
    <Nullable>enable</Nullable>
    <PublishAot>true</PublishAot>
    <RuntimeIdentifier>win-x64</RuntimeIdentifier>
    <SelfContained>true</SelfContained>
    <SuppressTrimAnalysisWarnings>true</SuppressTrimAnalysisWarnings>
  </PropertyGroup>
  <ItemGroup>
    <!-- Reference the local SDK DLL -->
    <Reference Include="MewgenicsModSdk">
      <HintPath>sdk\MewgenicsModSdk.dll</HintPath>
    </Reference>
  </ItemGroup>
</Project>
Automatic IntelliSense The MewgenicsModSdk.xml file must be in the same folder as the DLL. Visual Studio and Rider detect it automatically and display documentation tooltips.

3. Build the mod

# Debug (fast, for testing)
dotnet build

# Release NativeAOT (final DLL for the game)
dotnet publish -c Release -r win-x64

The published DLL is at bin\Release\net8.0\win-x64\publish\MyMod.dll.

4. Install the mod

  1. Copy MyMod.dll into the game's Mods/ folder (next to Mewgenics.exe).
  2. Launch Mewgenics.exe — the framework loads all mods automatically at startup.
  3. Press F1 in-game to open the overlay and enable your mod.
Config files Config files are stored at Mods/config/{mod_id}.cfg. They can be edited manually while the game is not running.

Gon — Data API

All game data (items, sets, events, abilities…) lives in the GPAK archive. The Gon class provides unified read/write access to both GON files and CSV localization. Reads always reflect the latest state, including any writes made via Set().

Use Gon.OnReady() The GPAK loads asynchronously after the game starts. Always wrap data-loading code in Gon.OnReady(callback) — never call Gon.From() directly in OnLoad().

GonNode.Add — Adding New Content

GonNode.Add(string gonText) is the primary API for creating new game content at runtime. It appends one or more GON blocks to a node and — when the path maps to a known catalog prefix — automatically injects them into the native SpawnDB. Injections survive SpawnDB rebuilds (save/load cycles) automatically; no hook infrastructure is required.

Gon.From() never returns null. For unknown paths it returns an empty node with path context set, ready for .Add(). Once you call .Add() the path is registered and subsequent Gon.From(path) calls return the same instance — any Set() modifications persist.

Adding new content to a game catalog

Gon.OnReady(() =>
{
    Gon.From("data/items/weapons.gon").Add(@"
        MySword { name MY_SWORD_NAME  rarity rare  kind weapon  str 5 }
    ");
});

Because the path begins with data/items/ the entry is automatically injected into the items SpawnDB catalog.

Adding mod config data (no SpawnDB)

Gon.From("mods/mymod/config.gon").Add(@"
    Settings { difficulty 3  multiplier 1.5 }
");

// Read it back anywhere:
int diff = Gon.From("mods/mymod/config.gon")["Settings"]["difficulty"].AsInt(1);

Paths outside the catalog prefixes are managed-only — stored in memory and accessible via Gon.From(), never injected into the native SpawnDB.

Chaining multiple Add calls

Gon.From("data/passives/my_passives.gon")
   .Add(@"MyPassiveA { name MY_PASSIVE_A_NAME  1 { passives { StrengthUp 2 } } }")
   .Add(@"MyPassiveB { name MY_PASSIVE_B_NAME  1 { passives { DexUp 2 } } }");

BreedWith

GameChar? BreedWith(GameChar partner) — breed two cats and return the resulting kitten.

  • Mom/dad roles assigned automatically by Gender (0 = female → mom).
  • The kitten is inserted into CatDB and its visual entity is spawned — it appears in the house immediately.
  • All genetics (stats, body parts, spells, colour) are computed by the game engine.
  • Thread-safe: can be called from any thread. Auto-marshals to the game thread when needed. No GameThread.Enqueue required.
  • Returns null if either cat is invalid, the world is not loaded, or the engine fails.

Content Injection

The SDK provides two approaches for adding new content at runtime.

  • GON-based (Gon.From(path).Add(gonText)) — parses a GON text block and injects every top-level entry into the appropriate SpawnDB catalog based on the file path prefix. Use this for new items, abilities, passives, or any content that requires its own definitions. See GonNode.Add.
  • Clone-based (RegisterItem on MewgenicsMod) — shallow-clones an existing entry and patches specific fields. Best for items similar to existing ones.
When to use which: use RegisterItem for simple stat/name tweaks on existing items. Use Gon.From(path).Add(gonText) when you need a truly new item with its own ability and passive definitions.

Register your content from OnLoad() using Gon.OnReady().

// Keeps gold, food and collars at configured minimums.

public class ResourceGuardMod : MewgenicsMod

Example 3 — Characters & Combat

Iterate player cats with GameWorld.GetPlayerCats(). Hook stat recalculation via OnStatRecompute and intercept damage via OnCatDamaged.

// Lists all player cats once, applies a configurable STR bonus on every
// stat recompute, and cancels all damage to player cats in God Mode.
public class CatInspectorMod : MewgenicsMod
{
    public override string Id          => "cat_inspector";
    public override string Name        => "Cat Inspector";
    public override string Category    => "Utility";
    public override string Description => "God Mode + STR boost + cat stats on load.";

    private bool _listed;

    protected override void OnLoad()
    {
        Config.GetBool("god_mode", false);
        Config.GetInt("str_bonus", 5);
        GameEvents.OnHouseUpdate   += HouseUpdate;
        GameEvents.OnStatRecompute += StatRecompute;
        GameEvents.OnCatDamaged    += CatDamaged;
    }

    private void HouseUpdate(HouseUpdateEvent e)
    {
        if (!IsEnabled || _listed) return;
        _listed = true;
        foreach (var cat in GameWorld.Current.GetPlayerCats())
        {
            Log($"[{cat.Name}] {cat.ClassName} Lv{cat.Level}  " +
                $"STR={cat.Str} DEX={cat.Dex} CON={cat.Con} INT={cat.Int} SPD={cat.Spd} CHA={cat.Cha} LCK={cat.Lck}");
            Log($"  HP={cat.MaxHp}  Score={cat.BattleScore}  Mutations={cat.MutationCount}");
            Log($"  Attack={cat.Attack}  Spells={cat.Spell0},{cat.Spell1},{cat.Spell2},{cat.Spell3}");
            Log($"  Passives={cat.Passive0},{cat.Passive1}");
        }
    }

    private void StatRecompute(StatRecomputeEvent e)
    {
        if (!IsEnabled || !e.IsPlayer) return;
        // Flat bonus applied AFTER normal recompute — stacks correctly
        e.Cat.Str += Config.GetInt("str_bonus", 5);
    }

    private void CatDamaged(DamageEvent e)
    {
        if (!IsEnabled || !Config.GetBool("god_mode", false)) return;
        if (e.Target.IsPlayer) e.Cancel();   // absorb all damage to player cats
    }
}

Use Hook(rva, fn) to install an inline hook at any game function. The hook function must be static with [UnmanagedCallersOnly]. Call the original via _hook.Invoke(...). Use Memory.Read<T> / Memory.Write<T> for direct struct access.

// Intercepts the native SetGold function so gold can never decrease.
// Demonstrates HookSlot, [UnmanagedCallersOnly], and Memory.Read.
public class GoldLockMod : MewgenicsMod
{
    public override string Id          => "gold_lock";
    public override string Name        => "Gold Lock";
    public override string Category    => "Cheat";
    public override string Description => "Gold can only increase.";

    private static HookSlot _hook;
    private static bool _active;   // static — accessible from [UnmanagedCallersOnly]

    protected override void OnLoad()
        => _hook = Hook(GameAddressMap.FN_SET_GOLD,
                   (nint)(delegate* unmanaged<nint, int, void>)&SetGoldHook);

    protected override void OnEnable()  => _active = true;
    protected override void OnDisable() => _active = false;

    [UnmanagedCallersOnly]
    private static unsafe void SetGoldHook(nint self, int newVal)
    {
        if (_active)
        {
            // Read current gold directly from house struct at offset +0xB4 (180)
            int cur = Memory.Read<int>(self, 0xB4);
            if (newVal < cur) newVal = cur;   // clamp — never decrease
        }
        _hook.Invoke(self, (nint)newVal);
    }
}

// Breeds the two highest-scoring cats and logs the kitten's stats.
// Reads mutations on all cats. Removes old cats (IsOld flag).
// All actions triggered by flipping config booleans in the in-game overlay.
public class BreederMod : MewgenicsMod
{
    public override string Id          => "breeder_mod";
    public override string Name        => "Auto Breeder";
    public override string Category    => "Utility";
    public override string Description => "Breeds top cats. Flip 'breed' in overlay to fire.";

    protected override void OnLoad()
    {
        Config.GetBool("breed",          false);
        Config.GetBool("remove_old",    false);
        Config.GetBool("log_mutations", false);
        GameEvents.OnHouseUpdate += HouseUpdate;

    private void HouseUpdate(HouseUpdateEvent e)
    {
        if (!IsEnabled) return;

    private void BreedBestPair()
    {

        var mom  = cats.Where(c => c.Gender == 0 && c.CanBreed).OrderByDescending(c => c.GeneticScore).FirstOrDefault();

        if (!mom.IsValid || !dad.IsValid) { Log("No valid breeding pair found"); return; }
        Log($"Breeding {mom.Name} (score={mom.GeneticScore}) × {dad.Name} (score={dad.GeneticScore})");
        var kitten = mom.BreedWith(dad);
        if (kitten != null)
        {
            var k = kitten.Value;
            Log($"Born: {k.Name}  {k.ClassName}  STR={k.Str} DEX={k.Dex} CON={k.Con}  score={k.GeneticScore}");
        }
        else Log("Breeding failed");
    }

    private void RemoveOldCats()
    {
        int n = 0;
        foreach (var cat in GameWorld.Current.GetAllCats())
            if (cat.IsOld) { cat.Delete(); n++; }
        Log($"Removed {n} old cats");
    }

    private void LogMutations()
    {
        foreach (var cat in GameWorld.Current.GetPlayerCats())
        {

Example 17 — Custom Item with Named Passives

Creates a fully custom item (Terror Blade) with its own ability (Wrath Strike), a named passive definition (Bloodrage), and localized display text — all injected at runtime without touching any game files.

The framework handles all hook infrastructure automatically. Your mod only needs to call Gon.From(path).Add(gonText) and register text.

  • Text is registered via NativeTextTable.InjectText — immediately visible in tooltips.
  • The passive definition uses named level blocks (1 { passives { StrengthUp 3 } }) — the framework dispatches them transparently at combat time.
  • The ability requires all fields explicit — no template merging at runtime (see warning below).
  • The path prefix determines the catalog automatically: data/passives/* → passives, data/abilities/* → abilities, data/items/* → items.
using MewgenicsModSdk.Game;

public class TerrorBladeMod : MewgenicsMod
{
    public override string Id          => "terror_blade";
    public override string Name        => "Terror Blade";
    public override string Category    => "Items";
    public override string Description => "Adds Terror Blade — legendary weapon with custom passive.";

    protected override void OnLoad()
    {
        // 1. Register display text — visible immediately in tooltips and UI.
        NativeTextTable.InjectText(new Dictionary<string, string>
        {
            ["TERRORBLADE_NAME"]      = "Terror Blade",
            ["TERRORBLADE_DESC"]      = "A blade forged in rage. Grows stronger with each kill.",
            ["TERRORBLADE_WRATH_NAME"] = "Wrath Strike",
            ["TERRORBLADE_RAGE_NAME"]  = "Bloodrage",
            ["TERRORBLADE_RAGE_DESC"]  = "Killing an enemy grants Strength until end of combat.",
        });

        // 2. Inject GON once the GPAK is ready. No hooks required.
        Gon.OnReady(() =>
        {
            // Named passive — the  1 { passives { ... } }  level block is required.
            Gon.From("data/passives/terror_blade.gon").Add(
                "TerrorBladeRage { " +
                "  name TERRORBLADE_RAGE_NAME  desc TERRORBLADE_RAGE_DESC " +
                "  1 { passives { StrengthUp 3 } } " +
                "}");

            // Ability — ALL fields must be explicit (no template merging at runtime).
            Gon.From("data/abilities/terror_blade.gon").Add(
                "wp_TerrorBladeWrath { " +
                "  class MeleeAttackAbility  template melee_attack " +
                "  meta { name TERRORBLADE_WRATH_NAME } " +
                "  cost { move_points 0 act_points 1 mana 0 cantrip true } " +
                "  target { target_mode direction aoe_mode line min_aoe 1 max_aoe 1 " +
                "           aoe_considers_character_size true aoe_excludes_self true " +
                "           knockback_mode character_to_tile } " +
                "  graphics { animation weaponswing } " +
                "  damage_instance { damage 17 type melee " +
                "                    incidentally_collects_pickups false " +
                "                    effects { Bleed 3 Burn 2 } } " +
                "}");

            // Item — references ability and passive by their injected IDs.
            Gon.From("data/items/terror_blade.gon").Add(
                "TerrorBlade { " +
                "  name TERRORBLADE_NAME  desc TERRORBLADE_DESC " +
                "  rarity legendary  kind weapon  frame 2 " +
                "  str 3  spd 1  durability [18, 25] " +
                "  ability wp_TerrorBladeWrath " +
                "  passives { TerrorBladeRage 1 } " +
                "}");

            Log("Terror Blade injected");
        });
    }
}
Ability fields must be explicit. Injected abilities bypass process_gon_variants (the template-merging pass that runs at game startup). All fields the template would have provided (cost, target, graphics, damage_instance) must be written in full.
Named passive convention. The 1 { passives { ... } } level block is required — the framework's hook reads the level number from the item's passives entry at combat time and dispatches each sub-passive to the engine. Use a unique prefix for all modded IDs (e.g. TerrorBlade*) to avoid name collisions with other mods.
